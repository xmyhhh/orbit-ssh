# 关机、退出与恢复机制

## 行为约定

| 操作 | 行为 | 确认与数据保护 |
| --- | --- | --- |
| 关闭窗口 | 启用「关闭到托盘」且托盘可用时隐藏，否则退出 | 隐藏不清理会话、不丢弃编辑；真正退出时保留确认 |
| 托盘／菜单／Dock 主动退出 | 真正退出，不隐藏 | 未保存远程文件始终确认；活动会话遵循关闭确认偏好；取消后继续工作 |
| 系统关机、重启、注销 | 非交互式退出，不因 SSH 会话或托盘偏好否决系统请求 | 持续保存本地恢复草稿；限时刷新历史、取消传输、关闭连接与后台服务 |
| 系统取消尚未提交的退出 | 继续运行 | Windows 查询及取消通知、Linux 查询阶段不进行破坏性清理 |
| 睡眠、锁屏、休眠 | 不视为退出 | 不因电源挂起通知主动断开全部会话 |
| 强制结束进程、强制断电 | 不保证收到通知 | 只能恢复此前已成功写入本机磁盘的数据 |

## 清理时序

1. 确认是系统已提交的退出，或用户已确认主动退出。
2. 标记正在关闭，拒绝新建 SSH／本地终端／MCP 连接和新传输，防止清理后又出现新会话。
3. 独立执行本地历史落盘、MCP 停止、托盘移除；取消进行中的传输及连接请求，并并行关闭 SSH 和本地终端。
4. 所有清理共享最多 **3 秒**的预算，不按会话数量逐个叠加等待；到期记录日志并允许系统继续退出。超时不意味着所有后台任务已完成。
5. 多次退出通知复用同一次清理；旧的用户确认结果不能撤销已提交的系统退出。

不在系统退出阶段弹“是否结束 SSH 会话”，也不尝试自动上传远程编辑。活动终端里的命令、交互程序和文件传输不能保证自动续跑；重要远程任务请使用 `tmux`、`screen` 或服务管理器。

## 未保存远程文件

编辑器在编辑过程中将恢复副本写到应用配置目录的 `editor-drafts/`，而不是只在关机时保存。草稿按主机和远程路径隔离，包含原始版本信息；采用临时文件、同步和原子替换。目录和文件分别限制为当前用户访问（Unix 权限 0700／0600；Windows 实际访问权限以用户配置目录 ACL 为准）。

重新连接同一主机、打开同一路径时，可选择恢复或丢弃草稿。恢复只修改编辑器内容，仍需手动保存；若远程版本已变，不应自动覆盖服务器文件。成功保存、明确放弃修改时删除对应草稿；系统退出保留草稿。

草稿是**本地明文**，可能包含配置、密码等敏感文本；不上传云端，不写入日志。存储失败会显示错误，不能宣称修改已安全保存。磁盘故障、强制退出及最后一次自动保存之前的少量输入仍可能丢失，不保证逐字恢复。

## 平台处理

### macOS

- `applicationShouldTerminate:` 返回 `NSTerminateLater`，清理／用户决定完成后回主线程调用 `replyToApplicationShouldTerminate:`，不再立即取消系统退出。
- 使用退出 Apple Event 的原因区分关机、重启、注销和用户主动退出。
- Command-Q 的原生菜单项转到 AppKit 退出路径，避免被误当作关闭窗口；窗口关闭仍可隐藏到菜单栏。
- 原生退出 hook 不依赖状态栏图标创建成功；`SIGTERM`／`SIGINT` 另走非交互式退出兜底。升级 Wails 后应重新核对 delegate 和菜单行为。

### Windows

- 独立隐藏顶层窗口接收会话广播，不依赖 Explorer 或托盘图标创建成功。
- `WM_QUERYENDSESSION` 立即同意，不打开对话框，也不提前断开连接。
- `WM_ENDSESSION(FALSE)` 不清理；`WM_ENDSESSION(TRUE)` 才提交非交互式、限时退出。
- 不使用“阻止关机原因”来维持普通 SSH 后台会话，不将睡眠事件当作注销。

### Linux

- 监听 logind 的 `PrepareForShutdown`，提前持有 `shutdown:delay` 文件描述符；收到真正关机通知后，在处理完成或短时安全计时器到期时释放。延迟不超过服务给出的上限与本机 4 秒上限中的较小值；不申请无限期阻止关机的锁。
- 注册 GNOME SessionManager 客户端，`QueryEndSession` 立即同意、取消阶段不清理，`EndSession` 完成限时清理后回复；`Stop` 直接退出。D-Bus 通知校验发送者及对象路径。
- `SIGTERM`／`SIGINT` 独立兜底，不依赖托盘或 D-Bus。服务缺失、延迟锁权限不足时仍正常启动，但清理只可尽力执行。Wails 也监听终止信号，监听器的先后顺序不确定；本机监听器会独立提交系统退出，避免最终停留在关闭到托盘的状态。
- KDE／XFCE 等未实现 GNOME 会话接口的桌面，其注销依赖终止信号；系统关机有 logind 时仍走 logind 通知。服务重启后不自动重注册，保留信号兜底。不能承诺每种桌面都提供完整退出宽限期。

## 验证

自动化测试只能向测试拥有的窗口／模拟会话发送通知，不广播退出、不执行真实关机。

- Go：退出确认／取消、系统退出不弹窗、并发幂等、总超时预算、新连接拒绝、草稿隔离与恢复。
- macOS：`scripts/tests/macos-termination.m` 校验原生等待／回复、退出原因分类、菜单路由和旧回复忽略。
- Windows：查询立即同意、取消无副作用、提交触发一次清理，托盘不可用不影响接收。
- Linux：会话信号路由、查询阶段回复、取消及监听器清理。

发布前在三个系统分别手动检查：窗口关闭驻留；主动退出可取消；隐藏窗口下系统注销／重启不被会话提示阻止；重开后草稿可恢复且远程文件未被自动修改；退出后 MCP 端口、本地子进程和托盘图标正常清理。真实关机测试应先保存其他应用的工作，由测试人员主动发起。
